Cap. 2. Unitatea de învățare: Constructori și Destructori în POO

Studiu individual academic privind gestionarea întregului ciclu de viață al obiectelor în paradigma Programării Orientate pe Obiecte.

Subiect Analizat: Mecanismele fundamentale de alocare, inițializare a stării obiectelor și de eliberare a resurselor ocupate în memorie prin utilizarea constructorilor și a destructorilor.

A) Prezentarea conceptului teoretic

Constructori: Un constructor este o funcție sau metodă specială a unei clase care este invocată în mod automat de către sistem în momentul în care se creează o nouă instanță (un obiect). Rolul său principal este de a aloca spațiul necesar în memorie, de a inițializa atributele obiectului și de a asigura o stare inițială validă, sigură și consistentă.

Destructori: Un destructor este o metodă specială apelată în mod automat în momentul în care ciclul de viață al unui obiect se încheie (de exemplu, când obiectul părăsește contextul său de execuție) și acesta urmează să fie eliminat din memorie. Scopul său principal este de a efectua operațiuni de curățare și de a elibera resursele externe ocupate.

Caracteristici principale:

  • Constructorii au de regulă același nume cu cel al clasei și nu returnează un tip de date explicit (nici măcar tipul general void).
  • Multe limbaje orientate pe obiecte permit supraîncărcarea constructorilor (definirea mai multor constructori cu parametri diferiți pentru aceeași clasă, oferind flexibilitate la instanțiere).
  • Destructorii nu pot primi niciodată parametri și nu pot fi supraîncărcați, existând un singur destructor unic per clasă.

B) Explicarea modului de utilizare

În dezvoltarea de aplicații software, constructorii sunt indispensabili deoarece previn apariția obiectelor instabile sau parțial configurate în memorie, permițând injectarea dependențelor și definirea configurărilor obligatorii. Destructorii devin esențiali atunci când obiectele gestionează resurse critice de sistem care nu sunt curățate automat de către runtime (cum ar fi conexiuni active la baze de date, pointeri de memorie brută, socket-uri de rețea sau fișiere deschise pe disc), asigurându-se că acestea nu rămân blocate după distrugerea fizică a obiectului.

Concept Avantaje Dezavantaje / Limitări
Constructori Garantează consistența și validitatea datelor din momentul instanțierii; oferă flexibilitate majoră prin mecanismul de supraîncărcare. Gestionarea erorilor în interiorul lor poate fi complexă; includerea unei logici prea lungi sau grele încetinește crearea obiectelor.
Destructori Automatizează curățarea memoriei și a conexiunilor; previn apariția scurgerilor de memorie (memory leaks) și blocarea resurselor hardware. În sistemele cu management automat al memoriei (precum Garbage Collectors), momentul exact al rulării lor poate fi imprevizibil (nedeterminist).

C) Exemple practice (Pseudocod / Structură Conceptuală)

Mai jos este prezentat un exemplu care ilustrează structura logică standard pentru implementarea acestor concepte în cadrul unei clase:

// Definirea clasei conceptuale
Clasa GestionarResursa
{
    // Atribut privat
    Privat Text numeResursa

    // 1. Constructor implicit (fără parametri)
    Public GestionarResursa()
    {
        numeResursa = "Implicită"
        Afișează("Constructor apelat: Resursa implicită a fost configurată.")
    }

    // 2. Constructor cu parametri (Supraîncărcare)
    Public GestionarResursa(Text nume)
    {
        numeResursa = nume
        Afișează("Constructor apelat: Resursa " + nume + " a fost configurată.")
    }

    // Metodă pentru utilizarea obiectului
    Public Functionalitate()
    {
        Afișează("Se execută operațiuni cu resursa: " + numeResursa)
    }

    // 3. Destructor
    Metodă_Destruct()
    {
        Afișează("Destructor apelat: Resursa " + numeResursa + " a fost eliberată.")
    }
}

Explicația funcționării codului: Când programul instanțiază un nou obiect trimitând un parametru de tip text, se execută automat al doilea constructor. Obiectul își desfășoară activitatea prin metodele sale standard (cum ar fi Functionalitate()). În momentul în care execuția părăsește contextul de valabilitate al obiectului, mecanismul de management al memoriei apelează destructorul clasei pentru a închide în siguranță resursele active.

D) Concluzii

Managementul corect al constructorilor și destructorilor reprezintă pilonul central al stabilității unei aplicații software dezvoltate pe baza paradigmei POO. Înțelegerea completă a momentului în care un obiect ia naștere și a momentului în care este eliminat ajută la scrierea unui cod curat, stabil și optimizat din punct de vedere al utilizării resurselor hardware ale sistemului.

Cap. 3 Rezolvarea problemei algoritmice

Enunț Problemă: Într-o pușculiță se află $N$ monede de diferite valori cu greutatea totală $G$ grame. Greutatea fiecărei monede de o anumită valoare este dată în tabelul ce urmează. Elaborați un program care determină suma minimă $S$ care ar putea să fie în pușculiță.
Valoarea monedei (lei) Greutatea monedei (grame)
11
52
103
254
505

Implementarea optimizată în limbajul C++

#include <iostream>
#include <climits>
using namespace std;

int tool(int coin){
    if (coin==1) return 1;
    if (coin==2) return 5;
    if (coin==3) return 10;
    if (coin==4) return 25;
    if (coin==5) return 50;
}

int minCoins(int coins[], int m, int V)
{
    if (V == 0) return 0;
    int res = INT_MAX;
    for (int i=0; i<m; i++)
    {
        if (tool(coins[i]) <= V)
        {
            int sub_res = minCoins(coins, m, V-tool(coins[i]));
            if (sub_res != INT_MAX && sub_res + 1 < res)
                res = sub_res + 1;
        }
    }
    return res;
}

int main()
{
    int arr[100]; int S; int n;
    cout << " n= "; cin >> n; cout << endl;
    cout << " S= "; cin >> S; cout << endl;
    for(int i=0; i<n; i++)
        cin >> arr[i];
    cout << "suma minima de monede= " << minCoins(arr, n, S);
    cout << endl;
    return 0;
}

Rezultatul execuției și analiza

Programul determină corect, prin tehnica recursivității, numărul minim de monede necesare pentru a cumula suma cerută în funcție de maparea greutate-valoare introdusă de la tastatură, respectând complexitatea structurală impusă de enunț.
